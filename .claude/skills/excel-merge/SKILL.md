# 양식이 다른 엑셀 취합

제출자마다 양식이 다른 엑셀들을 공통 스키마 하나로 합치는 작업.
**새로 짜기 전에 이 저장소의 기존 구현을 먼저 읽어라.** 항목별로 참고할 파일이 다르다.

| 참고할 것 | 파일 |
|---|---|
| 4종 양식 판별, 기준월·환율 처리, 월별/누적 출력 | `복잡한 실적 합산/취합.py` |
| `[PASS]`/`[FAIL]` 검증 출력 형식 | `기초 실적 합산/scripts/정리.py` |
| 건수 대조 검증, UTF-8 BOM CSV, 부분 실패 처리 | `크롤링 실습/신청광구_통합.py` |

(`취합.py`는 검증을 경고 목록으로만 낸다. 새로 만들 때는 `정리.py`의 `[PASS]`/`[FAIL]`
형식까지 함께 쓰는 쪽이 낫다.)

## 진행 순서

이 순서를 지켜라. 특히 2번을 건너뛰고 바로 취합기를 짜면 검증할 기준이 없어진다.

1. **구조 파악** — 파일을 전부 열어 아래 표로 정리해 사용자에게 보고한다.
   데이터 시작 위치 / 세로형·가로형 / 시트 개수와 의미 / 계정명 표기 / 숫자가 숫자형인지 텍스트인지.
   **이 단계에서는 코드를 만들지 않는다.** 규칙은 사용자가 구조를 보고 정한다.
2. **정답 샘플 확보** — 가장 정돈된 파일 하나를 기준으로 삼거나, 사용자가 지정한
   정답 파일을 찾는다. 이게 있어야 취합기를 대조 검증할 수 있다.
3. **취합기 작성** — 아래 「양식 판별」·「함정」을 따른다.
4. **정답과 셀 단위 대조** — 행 수만 맞추지 말고 값까지 집합으로 비교한다.
   ```python
   ref_set - mine_set   # 정답에만 있는 행
   mine_set - ref_set   # 내 결과에만 있는 행
   ```
5. **다음 달 대응 확인** — 팀 목록·컬럼 위치·시트 개수를 코드에 적지 않았는지 되짚는다.

## 양식 판별 — 위치를 고정하지 말 것

행/열 번호를 코드에 박으면 다음 달에 컬럼 하나만 삽입돼도 깨진다.
「계정」「Account」「품목」 같은 **표식 셀을 찾아** 거기서부터 상대적으로 읽어라.

| 양식 | 판별법 | 처리 |
|---|---|---|
| 표준 세로형 | 「계정」 셀이 있고, 같은 행 오른쪽에 품목명들 | 행=계정, 열=품목 |
| 오프셋형 | 「계정」은 있는데 품목명이 한 행 아래. 위쪽에 제목·기준월·작성자 같은 메타 행 | 표가 오른쪽·아래로 밀린 것. 앵커 기준 상대 좌표로 읽는다 |
| 가로형 | 「품목」 셀이 있고, 같은 행 오른쪽에 계정명들 | **행/열이 반대.** 별도 파서가 필요하다 |
| 품목별 시트형 | 「Account」가 있고 값 컬럼 헤더가 `Amount` 같은 일반 명사 | 시트 하나 = 품목 하나. **품목명을 시트명에서 가져온다** |

판별은 파서를 차례로 시도해 `None`이 아닌 첫 결과를 쓰는 식으로 구현한다.
어디에도 안 맞으면 조용히 넘기지 말고 경고를 남긴다.

## 반드시 밟는 함정들

실제로 다 겪은 것들이다. 하나씩 확인해라.

**계정명이 팀마다 다르다.** 별칭 사전으로 표준화한다.
`판관비 = 판매관리비 = 판매비와관리비`, `매출 = 매출액`, `영업외수지 = 영업외손익`,
영문 제출도 있다 (`Revenue`, `COGS`, `SG&A`, `Non-op Income`).
**사전에 없는 이름은 절대 조용히 버리지 마라.** 경고로 알려야 새 표기를 발견할 수 있다.

**소계·합계 행이 데이터에 섞여 있다.** `매출총이익`·`영업이익`·`세전이익` 같은 소계와
맨 아래 `Total`·`총계` 행은 인식은 하되 결과에 담지 않는다. 담으면 이중 계산된다.
소계는 버리는 대신 **검증 대조용으로 쓰면 좋다** (항목 합 vs 소계 vs 총계).

**숫자가 숫자형이 아니다.** 같은 시트 안에서도 열마다 다를 수 있다.
`"42 800 000 000"`(공백 구분), `"9,620,000"`(콤마), `"(120,000)"`(회계식 괄호 음수).
파서 하나로 셋 다 처리해라.

**기준월이 폴더명과 다를 수 있다.** 기본은 폴더명에서 얻되, **시트 이름 자체가 월코드**
(`2601`)면 그게 우선이다. 다음 달 파일 안에 지난달 시트가 정정본으로 딸려 오는 일이 잦다.

**환율·기준값은 레코드의 기준월로 찾아라.** ← 실제로 났던 버그.
"지금 처리 중인 폴더의 환율표"를 쓰면, 2월 폴더에 섞여 온 1월 데이터에 2월 환율이
붙는다. 모든 기간의 환율을 `{기준월: {통화: 환율}}` 로 미리 모아두고 레코드마다 조회한다.

**같은 데이터가 두 번 들어올 수 있다.** 정정본이 원본과 함께 집계되어 중복된다.
어느 쪽이 맞는지 **임의로 정하지 말고** 사용자에게 물어라. 보통은 둘 다 남기고
`출처`·`정정여부` 같은 구분 컬럼을 붙이는 쪽이 정보 손실이 없다.

**빈 제출을 구분해라.** 헤더만 있고 데이터 행이 없는 파일이 온다. 0건으로 처리하되
경고를 남긴다. 조용히 넘기면 그 팀이 안 냈다는 걸 아무도 모른다.

**의미가 다른 필드를 같은 칸에 넣지 마라.** 이름이 비슷해도 단위가 다를 수 있다
(전체 면적 vs 필지별 면적). 합계가 조용히 틀어진다. 애매하면 별도 컬럼으로 둔다.

**키가 유일하지 않을 수 있다.** 한 건이 여러 행에 걸쳐 들어오는 구조가 흔하다.
건수를 셀 때 행 수와 고유 키 수를 구분해서 보고한다.

## 검증은 결과와 함께 낸다

매 실행마다 검증 결과를 같이 출력한다. `[PASS]`/`[FAIL]` 형식을 쓴다
(구현은 `기초 실적 합산/scripts/정리.py` 의 `check()` 참고).

```
[PASS] 물류팀 항목합계 vs 부서소계 : 9,600,000 vs 9,600,000 (차이 0)
[FAIL] 화학팀 항목합계 vs 부서소계 : 9,600,000 vs 9,300,000 (차이 300,000)
```

최소한 이 셋은 확인한다.
- 원본에 소계/총계가 있으면 그것과 대조
- 서비스·원본이 알려주는 건수와 실제 수집 행수 대조
- 매핑 실패·빈 제출·양식 불일치는 경고 목록으로

**한 파일이 실패해도 나머지는 계속 진행하고**, 마지막에 실패 목록을 모아 보여준다.

## 출력 규칙

- **원본 파일은 절대 수정하지 않는다.** 결과는 `출력/` 폴더나 별도 파일로만 쓴다.
  사용자가 준 "정답/양식 파일"에 append하지 마라 — 물어보고 별도 파일로 내는 게 안전하다.
- 월별 산출물은 `{yymm}_취합.xlsx` 처럼 기간을 파일명에 넣는다. 실행할 때마다 그 달
  파일만 새로 쓰고 다른 달은 건드리지 않는다.
- 누적본처럼 덮어쓰면 곤란한 산출물은 **날짜+순번**을 붙인다
  (`실적_누적_260810_1.xlsx`, 같은 날 다시 돌리면 `_2`). 기존 파일을 덮지 않는다.
- CSV로 낼 때는 **UTF-8 BOM**(`encoding="utf-8-sig"`)을 쓴다. 안 그러면 엑셀에서 한글이 깨진다.
- 컬럼 순서는 원본 필드 순서를 유지한다.
- CSV 셀이 `=`, `+`, `-`, `@` 로 시작하는 **문자열**이면 앞에 `'`를 붙인다(수식 실행 차단).
  **숫자형 음수는 그대로 둔다** — 안 그러면 계산이 깨진다.

## 실행 환경 메모

- 콘솔 한글 깨짐 방지: 스크립트 앞에
  `sys.stdout.reconfigure(encoding="utf-8")` / `sys.stderr`도 같이.
- 이 저장소는 venv·requirements 없이 `py`로 바로 실행한다.
  `기초 실적 합산`은 pandas, `복잡한 실적 합산`은 openpyxl을 직접 쓴다.
- 스크립트는 작업 폴더 최상위에 둔다 (`scripts/` 하위로 내리지 않는다).
